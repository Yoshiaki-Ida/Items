# マニュアル統合・構築仕様（MVP）

## 1. 目的

個別HTMLを部品として管理し、GUIで定義した順序と最大3階層の構成から、採番・目次付きの完成版HTMLを決定論的に生成する。

## 2. プロジェクト構成

```text
manual_project/
├─ source/              # 個別HTML
├─ manual.yaml          # 構成。章番号は保持しない
├─ assets/              # 共通画像・CSS
└─ output/
   ├─ manual.html
   └─ build-report.json
```

GUIで新規作成する場合は`manual_project/`を選択する。`source/`内のHTMLを列挙し、`manual.yaml`はプロジェクトルートへ保存する。HTMLフォルダを直接選択する従来操作も互換経路として扱い、その場合は選択フォルダを`source_dir: .`とする。

## 3. YAML Schema

```yaml
version: 1
manual:
  title: 製品マニュアル
  source_dir: source
  output: output/manual.html
chapters:
  - id: overview
    title: 概要
    file: overview.html
  - id: basic-operation
    title: 基本操作
    children:
      - id: startup
        title: 起動
        file: startup.html
```

- `id`: 英字で始まる英数字・ハイフン・下線。番号変更の影響を受けない参照キー。GUIでの保存や並べ替えでも既存IDを維持し、欠落・不正・重複時だけ内容由来のIDを補完する。
- `title`: 完成版に表示する見出し。
- `file`: `source_dir`からの相対HTMLパス。
- `numbered`: 省略時は`true`。`false`の場合、本文と目次には含めるが章番号は表示しない。
- `children`: 子項目。章・節・項の3階層まで。
- 章番号は保存しない。
- HTMLを持つ項目も子要素を持てる。子要素は章構成上の下位番号として出力する。
- `manual.output`は、構成に登録した入力HTMLとは別のファイルを指定する。同一ファイルを指定した場合は、原本保護のため構築を拒否する。

## 4. 個別HTML

- UTF-8の`.html`または`.htm`。
- 最初の見出しは空でない`h1`とし、`h1`は1つだけとする。
- 後続見出しは`h2`から始め、レベルを飛ばさない。
- 個別ファイル作成時に既存の`2.`、`２．２．`など半角・全角・混在の番号を認識し、ファイル内の階層から`１．`、`１．１．`のような全角の相対番号へ振り直す。
- 構築時は部品内の相対番号を除去し、YAMLの構成から計算した番号で置き換える。
- 構築時はYAMLのタイトルで部品の`h1`を置き換え、配置階層に応じて後続見出しをシフトする。

## 5. 構築

1. YAMLをUTF-8で読み込む。
2. Schema、階層、ID、タイトル、重複、HTML、見出し、参照ファイルを検証する。
3. 構成の順序と階層から番号を再計算する。
4. 個別HTMLの見出しレベルを調整して結合する。
5. 全見出しを含むアンカー付き目次を生成する。採番対象外の見出しも番号なしで掲載する。
6. A4用紙の画面表示・印刷CSSを適用し、最上位の章は必ず新しいページから開始する。節・項、段落、表は前ページの空きへ続け、長い表は見出し行を繰り返して行単位で改ページする。
7. レイアウト確定後に目次へページ番号を表示する。
8. ローカル画像・CSS等を出力フォルダへコピーし、参照を出力基準へ変更する。再構築時は、前回の生成一覧に存在し今回生成しなかったアセットだけを削除し、一覧外のファイルは変更しない。
9. `manual.output`と同じフォルダへ`build-report.json`を生成し、`generated_files`へ今回コピーしたアセットの相対パスを記録する。

元HTMLとYAMLは構築処理で変更しない。同じ入力からは同じ`manual.html`を生成する。

## 6. 相互参照の拡張点

個別HTMLの`<a data-ref="home-operation"></a>`は、構築時に安定IDのアンカーへ解決する。リンク文字列が空の場合は、その時点の番号とタイトルを自動設定する。

## 7. MVP対象外

- PDF生成
- Wordへの逆変換
- AI／クラウド連携
- 高度な相互参照書式
- 個別HTML内のJavaScript実行
