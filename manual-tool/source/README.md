# ManualTool

個別HTMLを部品として、マニュアルの構成を決め、同じ構成から完成版HTMLを繰り返し生成するPoCです。

## 主な機能

### 1. GUIでマニュアル構成を編集

ブラウザ上で個別HTMLの順序と最大3階層の構成を編集し、`manual.yaml`として保存します。

* 未使用HTMLを構成へ追加
* 上下移動、インデント、アウトデントで章・節・項を編集
* タイトルと採番対象を設定
* 保存済みの`manual.yaml`を読み込み、編集を継続
* GUIから完成版HTMLを構築

### 2. 決定済み構成から完成版を自動構築

保存した`manual.yaml`を入力に、章番号、目次、ページ番号を持つ統合HTMLを決定論的に生成します。構築時に構成と個別HTMLを検証し、元のHTMLとYAMLは変更しません。

* YAMLの順序と階層から`1.`、`1.1.`、`1.1.1.`形式の番号を再計算
* 個別HTMLの見出しレベルを調整して結合
* アンカー付き目次とページ番号を生成
* A4表示・印刷用レイアウトを適用
* 画像・CSSなどのローカル資産を出力先へコピー

## セットアップ

WindowsとPython 3.11以上が必要です。セットアップはこのフォルダ内に仮想環境を作成します。

```powershell
Set-Location .\Items\manual-tool\source
.\scripts\setup.ps1
```

## Windows向け配布パッケージを作成する

Windows向けの配布物は、セットアップ後にこのフォルダで作成します。PlantUML対応も含める場合は、先に配布フォルダのJARとライセンスをコピーします。Java本体は初回セットアップで取得されます。

```powershell
New-Item -ItemType Directory -Force .\runtime\plantuml
Copy-Item -LiteralPath ..\_internal\runtime\plantuml\plantuml.jar, ..\_internal\runtime\plantuml\PLANTUML-LICENSE.txt -Destination .\runtime\plantuml
```

次のコマンドで配布フォルダとローカル配布用ZIPを作成できます。

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\scripts\package.ps1
```

`dist/ManualTool/` と `dist/ManualTool-windows.zip` が生成されます。ZIPを展開し、同梱の`ManualTool.bat`を実行するとブラウザ版が起動します。操作手順は配布物内の`docs/USER_GUIDE.html`で確認できます。TeamsへHTMLを単体で添付する場合は、画像を埋め込んだ`docs/USER_GUIDE_EMBEDDED.html`を使用してください。配布物はWindows専用で、PandocによるOMML数式変換やMicrosoft Visioによる図面変換は利用者の環境にインストールされている場合だけ有効です。未導入時は既存のフォールバック処理が使われます。

## GUIで構成を編集する

```powershell
.\scripts\manual-edit.bat
```

ブラウザで起動した画面から「マニュアル編集」を選択し、`source/`を含むプロジェクトルートを開きます。構成を整えてタイトルを設定すると、プロジェクトルートへ`manual.yaml`を保存します。同じ画面で「マニュアル構築」を実行できます。従来互換として、個別HTMLがあるフォルダを直接選択することもでき、その場合は選択フォルダ直下へ`manual.yaml`を保存します。

保存後に構成またはタイトルを変更した場合は、再保存するまで構築できません。

## 保存済み構成から自動構築する

```powershell
.\scripts\build.bat "C:\manual_project\manual.yaml"
```

`manual.yaml`の既定のプロジェクト構成は次のとおりです。

```text
manual_project/
|- source/              # 個別HTML
|- manual.yaml          # GUIで保存した構成
|- assets/              # 共通画像・CSS
`- output/
	|- manual.html
	`- build-report.json
```

YAMLの詳細と検証仕様は[マニュアル統合・構築仕様](docs/MANUAL_ASSEMBLY_SPEC.md)を参照してください。

## 補足機能

### 個別ファイルの変換・編集

#### 対象形式

Word（`.docx`）、Markdown（`.md`、`.markdown`）、HTML（`.html`、`.htm`）を個別HTMLへ変換し、Lint、自動修正、プレビューを行えます。GUIでは「個別ファイル編集」を選択します。

#### フォルダを開く・書き出す

文書は「フォルダを開く」から対象フォルダを選び、左側のツリーから開きます。HTMLと同階層の相対画像を確実にセッションへ取り込むため、HTML単体のファイル追加とドラッグ＆ドロップは提供しません。

フォルダへ書き出すと、画像は選択先の`images/<文書名>/`へ保存され、生成HTMLと補助Markdownから相対参照されます。

#### Visio・画像資産の変換

WordにVisio図面が埋め込まれている場合は、元の`.vsd`または`.vsdx`を`visio/<文書名>/`へ保存し、Microsoft VisioでPNGへ変換して`images/<文書名>/visio/`へ配置します。プレビューと生成HTMLは表示用EMFではなくPNGを参照します。PNG変換に失敗した図面は、元の表示用画像をそのまま使用します。

Visio埋め込み以外のEMF/WMF画像も同じ変換処理でPNG化し、ブラウザで直接表示できるPNGへのリンクへ差し替えます。元からPNGの画像は変換せず、そのまま使用します。元のEMF/WMFも画像資産として保持します。

#### Lint・プレビュー

Lintで「無視」にした指摘は画面から除外されます。ダウンロードまたは書き出しした`lint-report.json`には監査履歴として残り、`ignored: true`で未処理の指摘と区別されます。

指摘欄の「Markdown出力」で、表示中の指摘を重要度・対象行・ルール・指摘内容・修正案の表としてダウンロードできます。HTMLをフォルダに書き出す場合も、補助フォルダに `lint-report.md` が生成されます。

プレビュー生成中は進捗インジケーターと経過秒数を表示します。文書量やブラウザ描画時間で完了時刻が変わるため進捗率は表示せず、iframeの描画完了後に実測時間を表示します。文書を素早く切り替えた場合は古い生成結果を破棄し、表示完了したプレビューだけを差し替えます。

#### PlantUMLの図とHTML上での編集

ソースからの起動でPlantUMLを使う場合は、Javaを `PATH` または `JAVA_HOME` で利用できるようにし、`MANUAL_TOOL_PLANTUML_JAR` にローカルのPlantUML JARのパスを設定します。配布版のJARを使う場合は、このフォルダから次のように設定できます。

```powershell
$env:MANUAL_TOOL_PLANTUML_JAR = (Resolve-Path ..\_internal\runtime\plantuml\plantuml.jar).Path
```
Markdownの `plantuml` コードブロックは、HTML生成時にSVGへ変換されます。
外部ファイルやURLを読み込むPlantUMLディレクティブは使用できません。

HTMLをブラウザで開き、ManualToolのWebモードを起動した状態で「PlantUMLソース」を
編集すると、入力が止まった時点で図が更新されます。ブラウザからローカルネットワークへの
アクセス許可を求められた場合は、ManualToolとの通信を許可してください。
「HTMLを保存」で原文と最新の図を含むHTMLをダウンロードできます。
相対パスで画像を参照するHTMLは、保存したファイルを元のHTMLと同じフォルダに置いてください。
閲覧とブラウザでの印刷・PDF化にはWebモードの起動は不要です。印刷には図が載ります。

#### 編集ビューでの選択と位置同期

「編集ビュー」では、中央のHTML表示から見出し、本文、表セル、Note / Warning、画像をクリックし、右側のプロパティから内容を変更できます。見出しの章・節番号は読み取り専用で、本文だけを編集します。元データ、プレビュー、編集ビューのスクロール位置は連動し、プレビュー上の編集可能な要素をクリックすると同じ要素を選択した編集ビューへ切り替わります。行番号を持つLint指摘をクリックすると、元データの該当行へ移動します。

#### 文章・画像ブロックの編集

画像はPNG、JPEG、GIF、WebPの差し替えに加え、選択ブロックの前後への追加と選択画像の削除に対応し、セッション内の画像資産として保存します。文字列行は追加ダイアログから選択位置の前後へ挿入でき、背景なしまたは任意の背景色を指定できます。追加した文字列行と既存の通常本文には、なし・細線・太線から選べる下線と任意の線色を設定できます。GUIで追加した文字列行、通常本文、Note / Warningはブロック単位で削除できるため、文字を消して背景だけになった領域も除去できます。見出し、本文、リスト項目、表セル、Note / Warning、文字列行は6～72ptの範囲でフォントサイズを指定でき、太字も切り替えられます。入れ子のリスト項目は子リストを保ったまま、その項目の本文を編集します。サイズを空欄に戻すと既定サイズへ戻り、太字のチェックを外すと通常の太さへ戻ります。

#### 表の編集

表は選択位置の後への新規挿入、選択セルを基準とした行・列の前後追加および削除に対応します。表セルを1つ選択し、横幅を6～720ptの範囲で指定すると選択セルが属する列だけへ、縦幅を指定すると選択セルが属する行だけへ適用します。空欄で反映すると対象の列または行だけを既定寸法へ戻します。選択セルの背景色は変更または透明化でき、文字を削除した後に残った塗りだけを消すこともできます。最後の行または列を削除した場合は表全体を削除します。`rowspan`または`colspan`による結合セルを含む表は、対応する列・行を一意に判断できないため、セル内容と背景色の編集だけを許可し、行列の構造・寸法操作を無効にします。

#### 編集内容の保存と制約

「HTML編集を保存」で変更を既存のMarkdownセッションへ決定論的に反映し、通常プレビュー、Lint、HTML書き出しにも引き継ぎます。編集ビューではHTMLタグ、CSS、章・節番号を直接変更できません。背景色と下線色はGUIが生成した6桁カラーまたは透明、下線幅は細線・太線の固定値、フォントサイズは6～72pt、太字は固定のfont-weight、表セル寸法は6～720ptの許可値だけを保存処理で正規化し、それ以外のstyle指定は除去します。見出しなど文字列行以外の一般ブロック追加、ドラッグ移動、数式編集、Visio編集はMVPの対象外です。

#### 文書読み込みの進捗

フォルダ内文書のオープン中も、Word変換、埋め込みVisioやEMF/WMFのPNG変換を含む読込処理が終わるまで、経過秒数付きの進捗インジケーターを表示します。

#### 数式変換

Word内のOMML数式はPandocでMathMLへ変換し、プレビューと生成HTMLでもMathML要素として保持します。

#### テキストボックス・複合図

Wordの画像や図形に重ねられたテキストボックスは、変換専用コピー内で通常の段落へ昇格してからHTML化します。背景画像は維持し、互換表示用に重複しているテキストは1件へまとめます。

Word上で複数の画像・図形・テキストを組み合わせた複合図や埋め込みオブジェクトは、元の画像やVisioプレビューを使って変換します。Word上の重ね合わせや一部要素をHTMLで完全に再現できない可能性がある位置には注意文を挿入し、原本確認が必要な箇所を明示します。完成図全体の再画像化や派生VSDX生成は行わないため、元のVisioデータを画像へ劣化させず、読込時間の増加も抑えます。

#### blockquoteの扱い

Wordの段落書式が引用として解釈されて生成された`blockquote`は、表内・通常文章とも初回のWord変換時に解除します。子要素、文字、強調、リンク、画像は維持し、変換上の注意として後から生成するブロックは残します。HTMLファイルに明示された引用はWord由来ではないため維持します。

#### 文書の再選択

フォルダ内で既に開いている文書を再選択した場合は、新しい編集セッションを増やさず、既存の文書へ切り替えます。

#### コマンドライン変換

コマンドラインから変換する場合:

```powershell
.\scripts\manual-convert.bat "C:\manuals\sample.docx"
.\scripts\manual-convert.bat "C:\manuals\a.md" "C:\manuals\b.html" --output-dir "C:\manuals\output"
```

主なオプション:

* `--no-auto-fix`: 自動修正を無効化
* `--fail-on-error`: Lint ERRORがあれば終了コード1
* `--rules <path>`: 別のLintルールを使用
